JSON doesn't mess around!

Day 1 reflection:

I searched the browser for dog API. The request was input into the browser and I got a response back with raw JSON. I was able to make it Pretty Print by clicking Prettier in the response page. What I got back was JSON that resembles an object only the code was not active. JSON requires double quotes on field names and is basically just an image of actual code or an object. Any small mis-step in JSON will not be JSON at all. Pretty looks better and is easier to read.

Step 2-Postman

I started with an Api and minimized the query to 1. After I saw the value of 1 listed in the Headers request section I modified the query to 10. I got an object with 10 properties but upon searching for a query of 20 there was no change and a value of 10 remained.

Api key was ran normal the first time which left the key id visible and exposed. To secure the key in the Headers a value of api-key wrapper in double brackets was input in the value box. Then I went into the variables section and secured the key so it would only appear as dotted out.

Day 2 reflection:

I sent the request off and got back, hidden in the address bar, a status code that consisted of three digits, 200, which assured me that my request was understood or found by the server. A red highlighted 404 would mean that my request was not found. I also played around with the query parameter. This gave me the opportunity to be more detailed in my search and tell API how to answer my question.
